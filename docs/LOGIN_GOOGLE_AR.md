# الدخول بالموبايل وجوجل

## السلوك

- `/login` يستخدم التصميم الثاني «البطاقة الهادئة»، مع اللوجو الأصلي واسم Multi Task Agency.
- تسجيل الدخول بكلمة المرور يقبل رقم الموبايل الأساسي المسجل فقط؛ الإيميل لا يعمل كاسم دخول. كود تأكيد البريد أثناء إنشاء الحساب باقٍ كما هو.
- الأرقام العربية والفارسية والصيغة المصرية المحلية و`+20` و`0020` تصل لنفس الحساب. الأرقام الإضافية للعميل لا تصبح بيانات دخول.
- `/adminmt/login` يحول لنفس بوابة الدخول. الدور يحدده الخادم، وتظل صلاحيات العميل والفريق واشتراط تغيير كلمة المرور مطبقة.
- جوجل لا ينشئ عميلًا مكررًا ولا يربط بالإيميل تلقائيًا. أول مرة يختار المستخدم حساب جوجل ثم يؤكد حساب الموقع بالموبايل وكلمة المرور. الزيارات التالية تدخل بنفس حساب الموقع من جوجل مباشرة.
- العميل الجديد ينشئ حساب الموقع أولًا من `/register` مع كود البريد، ثم يمكنه ربط حساب جوجل. البريد القادم من جوجل لا يستبدل بريد التفعيل أو بيانات العميل.
- اختيار «نسيت كلمة المرور» يوضح طريقة التواصل مع الإدارة للحصول على رابط الاستعادة الموجود بالفعل في النظام.

## إعداد جوجل الفعلي

لا يوجد Client ID خاص بهذا الموقع ضمن الملفات المحلية؛ لم يُختبر الدخول بحساب Google حقيقي. المكتبة والربط والتحقق جاهزون، وتظل خاصية جوجل غير مفعلة حتى اكتمال الإعداد التالي.

1. افتح Google Auth Platform في مشروع الشركة: https://console.cloud.google.com/auth/clients
2. اضبط اسم التطبيق Multi Task Agency واللوجو وبريد الدعم والنطاق `multitaskagency.com`، وصفحة الخصوصية التابعة للموقع. استخدم بيانات الشركة الحقيقية.
3. أنشئ OAuth Client من النوع **Web application**.
4. أضف مصدر JavaScript المعتمد `https://multitaskagency.com`. للتجربة المحلية استخدم `http://localhost` و`http://localhost:5173` وافتح المعاينة بهذا الاسم؛ Google لا يعتمد عناوين IP المحلية المعتادة مثل 127.0.0.1 كبديل للنطاق.
5. انسخ **Client ID** فقط إلى إعداد الخادم أدناه. هذا المسار يستخدم Google Identity Services JavaScript callback، ولا يحتاج Client Secret أو Redirect URI.
6. إذا كان مشروع Google في وضع Testing أضف حساب التجربة إلى Test users. قبل إتاحته لكل العملاء استكمل إعداد الجمهور والنشر المطلوب من Google.

داخل `api/config.php` الخاص بالخادم، أو متغير بيئة الخادم:

```php
'google_auth' => [
    'enabled' => true,
    'client_id' => getenv('MT_GOOGLE_CLIENT_ID') ?: 'YOUR_WEB_CLIENT_ID.apps.googleusercontent.com',
    'certificate_cache_dir' => dirname(__DIR__, 2) . '/private_runtime/google-auth',
],
```

فعّل امتدادي PHP `openssl` و`curl`، واسمح بالاتصال الآمن إلى `https://www.googleapis.com/oauth2/v1/certs`. مجلد الشهادات المؤقت يجب أن يكون قابلًا للكتابة وخارج `public_html`؛ ينشئه التطبيق عند الإمكان. فشل التخزين المؤقت لا يمنع التحقق، وفشل جوجل لا يمنع الدخول بالموبايل.

تمت إضافة نطاقات GIS المحددة إلى CSP في `.htaccess` مع الإبقاء على `same-origin-allow-popups`. ارفع الملف مع التحديث؛ وضع الواجهة وحده لا يكفي.

## قبل الرفع

- راجع الحسابات القديمة التي ليس لها رقم موبايل، خصوصًا المالك والفريق؛ النظام القديم كان يسمح بحساب يعتمد على الإيميل فقط. لم يتم تعديل بيانات الإنتاج أو تخمين أرقام أصحاب الحسابات.
- أضف أرقامهم الصحيحة من إدارة المستخدمين قبل تفعيل منع الدخول بالإيميل. حافظ على جلسة مالك مفتوحة وتحقق من دخول المالك بالموبايل في نافذة منفصلة.
- راجع تكرار الرقم بصيغ مختلفة بين حسابات قديمة. التحديث يمنع إنشاء تكرارات جديدة عبر التسجيل وإدارة المستخدمين وتعيين بيانات دخول العميل، ويرفض اختيار حساب عشوائي إذا كان التكرار موجودًا بالفعل.
- ارفع ملفات PHP الجديدة والمكتبة `api/vendor/firebase-php-jwt` مع رخصتها، وملف `database/mysql/043_google_auth.sql`، وملفات الواجهة المبنية و`.htaccess`.
- التحديث 043 إضافي لإنشاء جداول ربط جوجل والمحاولات المؤقتة، ويمكن تطبيقه صراحة أو ينشئه مسار جوجل عند الحاجة تحت قفل قاعدة البيانات.
- إعداد SMTP لإرسال كود البريد مستقل عن إعداد جوجل ويظل مطلوبًا للتسجيل العادي.

استعلام فحص مبدئي للحسابات النشطة دون موبايل (قراءة فقط):

```sql
SELECT id, full_name, role, phone
FROM users
WHERE is_active = 1 AND (phone IS NULL OR TRIM(phone) = '');
```

## التحقق والحماية

- التوقيع عبر مكتبة `firebase/php-jwt` الإصدار 7.1.1 من مستودع Google الرسمي، مع التحقق من RS256 والمصدر والجمهور والصلاحية والـ nonce. المصدر وبصمات الملفات في `api/vendor/firebase-php-jwt/UPSTREAM.json`.
- كل محاولة مرتبطة بمتصفحها، صلاحيتها خمس دقائق، ولا يمكن إعادة استخدامها. ربط الحساب يتطلب كلمة المرور الصحيحة، ويرفض الحسابات الموقوفة وتعارض الروابط.
- لا تُحفظ توكنات جوجل في التخزين المحلي أو سجلات التطبيق؛ يستخدم النظام معرّف `sub` الثابت بعد التحقق فقط.
- النسخ الاحتياطية تستبعد محاولات الدخول المؤقتة وتحتفظ بروابط الحسابات. استعادة النسخة تحافظ على ربط المالك الحالي مع حسابه المحفوظ وتلغي محاولات جوجل المعلقة.
- اختبارات `tests/googleAuth.test.php` تستخدم مفاتيح RSA مولدة وقاعدة SQLite منفصلة؛ لا تحاول الدخول بحسابات حقيقية.
