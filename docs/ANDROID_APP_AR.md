# تطبيق MT Agency لأندرويد

التطبيق مبني كتطبيق Android موثوق يعرض الموقع الحي `https://multitaskagency.com`، ولذلك تظهر تحديثات الموقع داخله فور نشرها من دون إصدار APK جديد. يلزم إصدار جديد فقط عند تغيير اسم التطبيق أو الأيقونة أو معرّف الحزمة أو صلاحيات Android الأصلية.

## الملفات الحساسة

- احتفظ بنسخة آمنة من `android-twa/android.keystore` وكلمة مروره خارج الجهاز.
- لا تُرفع ملفات التوقيع إلى GitHub أو Hostinger.
- يجب توقيع كل تحديث مستقبلي بالمفتاح نفسه وإلا سيرفض Android تثبيته كتحديث.

## الثقة بين الموقع والتطبيق

ملف `public/.well-known/assetlinks.json` يربط نطاق الموقع بمعرّف الحزمة `com.multitaskagency.app` وبصمة مفتاح التوقيع. يجب نشره كما هو وبنوع محتوى JSON، ثم يمكن فحصه من:

`https://multitaskagency.com/.well-known/assetlinks.json`

## تفعيل إشعارات Firebase

1. أنشئ مشروع Firebase وأضف Web App باسم MT Agency.
2. فعّل Cloud Messaging وأنشئ Web Push certificate للحصول على مفتاح VAPID العام.
3. أنشئ Service Account للتطبيق، ونزّل ملف JSON وضعه خارج `public_html`.
4. في `api/config.php` فعّل قسم `push` وانسخ إعدادات Web App ومفتاح VAPID ومسار Service Account ومفتاح عامل طويلًا وعشوائيًا.
5. شغّل الترحيل `database/mysql/029_android_push_notifications.sql` على قاعدة Hostinger.
6. أضف Cron Job كل دقيقة. العامل ينشئ أيضًا تنبيهات استحقاق الدفع وقرب انتهاء الباقة قبل إرسال طابور Firebase:

```bash
curl -sS -X POST -H "X-Worker-Key: YOUR_LONG_PUSH_WORKER_KEY" https://multitaskagency.com/api/cron/push-queue
```

7. افتح التطبيق وسجّل الدخول واضغط **تفعيل الإشعارات**. تصل الإشعارات بصوت واهتزاز، ويتزامن رقم غير المقروء مع شارة التطبيق. شكل الشارة (رقم أو نقطة) تحدده واجهة الهاتف؛ بعض واجهات Android تعرض نقطة فقط.

الإصدار `1.0.1` يفعّل قناة Android عالية الأهمية ويربط رقم الإشعارات غير المقروء بالإشعارات النشطة. بعد نشر تحديثات الموقع يجب تثبيت ملف APK الموقّع للإصدار `1.0.1` مرة واحدة؛ بعد ذلك تبقى تغييرات الموقع لحظية كما كانت.

إذا بقي `push.enabled` بقيمة `false` فلن يظهر طلب الإذن ولن تتأثر إشعارات البرنامج الداخلية الحالية.

## بناء APK جديد

1. غيّر `appVersionCode` و`appVersion` داخل `android-twa/twa-manifest.json` عند إصدار نسخة جديدة.
2. شغّل `npm run build` ثم `npm run android:update`.
3. اضبط متغيري `BUBBLEWRAP_KEYSTORE_PASSWORD` و`BUBBLEWRAP_KEY_PASSWORD` ثم شغّل `npm run android:build`.
4. اختبر التوقيع والرابط الكامل قبل التوزيع أو الرفع إلى Google Play.


## تحديث 1.0.2 — المالك والعميل

- تحديثات الحجز والباقات ولوحتي المالك والعميل تأتي من الموقع نفسه؛ يلزم نشر آخر نسخة للموقع.
- يرسل الخادم أحداث الحسابات والباقات والمواعيد والمدفوعات بعد حفظها مباشرة. يبقى عامل Cron كل دقيقة لاستدراك الأعطال والتنبيهات المجدولة. لا تعتمد عملية الإرسال على بقاء جهاز المالك أو العميل مفتوحًا.
- من جرس الإشعارات في أي من اللوحتين اختر تفعيل إشعارات الجهاز؛ التجربة ترسل من الخادم إلى الجهاز المسجل للحساب الحالي فقط. عبارة «تم الإرسال» لا تثبت أن الهاتف عرضه أو أصدر صوتًا.
- يوفر التطبيق طلب صوت واهتزاز وقناة عالية الأهمية. العدّاد الداخلي يمثل غير المقروء؛ شارة أندرويد تعتمد على الإشعارات النشطة وواجهة الهاتف، وقد تكون رقمًا أو نقطة. لكل حدث إشعار واحد حتى لا يتضخم العدّاد عند جمعه من واجهة الهاتف.
- يمكن إغلاق نافذة التطبيق وقفل الشاشة بعد السماح بالإشعارات. يحتاج الهاتف اتصالًا بالإنترنت، وصلاحية إشعارات التطبيق/المتصفح والصوت وشاشة القفل. وضع عدم الإزعاج والإيقاف الإجباري وقيود البطارية قد يمنعان الصوت أو التسليم؛ لا يتجاوز التطبيق اختيارات النظام.
- على آيفون لا يوجد مشروع تطبيق أصلي في هذا المستودع. إشعارات الويب تحتاج نسخة iOS داعمة وتثبيت الموقع على الشاشة الرئيسية وإذن المستخدم؛ لا تعادل نسخة APK لأندرويد.

للتحقق على هاتف فعلي: ثبّت التحديث فوق النسخة السابقة، وفعّل الإشعارات من حساب المالك ثم حساب العميل على الجهاز المخصص لكل منهما. تأكد من وصول تجربة الخادم. أغلق التطبيق واقفل الشاشة، ثم نفّذ حدثًا حقيقيًا مصرحًا به من جهاز آخر. افحص التنبيه والصوت والأيقونة، ثم افتح الإشعار وتحقق من الصفحة الصحيحة وانخفاض العداد بعد القراءة. اختبارات العامل الآلية لا تغني عن هذه التجربة على الهاتف.

## تحديث 1.0.3 — هوية MTA

- الاسم الظاهر تحت الأيقونة وفي معلومات تطبيق Android هو MTA.
- تستخدم أيقونات Android والتثبيت من المتصفح وشاشة البداية شعار الشركة الأصلي، مع طبقة أحادية اللون للأيقونات الملوّنة من النظام والإشعارات.
- حافظ التحديث على معرّف التطبيق ومفتاح توقيعه؛ ثبّت النسخة الجديدة فوق الحالية دون حذف التطبيق.

## تحديث 1.0.4 — الإشعارات التلقائية

- عند أول تشغيل على Android 13 أو أحدث، يعرض التطبيق طلب إذن النظام مباشرة. يظل التطبيق قابلًا للاستخدام عند الرفض ولا يكرر الطلب تلقائيًا بعد رفضه.
- بعد الدخول بحساب المالك أو العميل يبدأ تسجيل الجهاز تلقائيًا، ويعاد عند الرجوع للتطبيق أو عودة الإنترنت. إذن سابق مسموح لا يحتاج زر تفعيل؛ إذا اشترط المتصفح تفاعلًا، تعاد المحاولة عند الاستخدام المعتاد.
- الصوت مفعّل افتراضيًا، مع احترام كتم المستخدم السابق وصوت قنوات Android ووضع عدم الإزعاج. زر الإعدادات متاح للفحص والتجربة اختياريًا.
- رسائل قبول ورفض الموعد وتغييره والدفع أصبحت صريحة. لا يوصف إثبات قيد المراجعة بأنه مرفوض، ولا يتحول تأكيد الحجز إلى إشعار تعديل لمجرد احتواء السجل على التاريخ والوقت.
- يلزم تثبيت APK الجديد فوق النسخة السابقة لتطبيق طلب إذن Android عند التشغيل. نجاح الاختبارات لا يثبت سماع الصوت على هاتف فعلي؛ يجب فحص ذلك على الجهاز.
