# تطبيق MT Agency لأندرويد

هذا المشروع يولد تطبيق Android من الموقع الحي `https://multitaskagency.com` باستخدام Trusted Web Activity.

- أي تحديث يُنشر على الموقع يظهر داخل التطبيق دون إصدار APK جديد.
- `enableNotifications` مفعّل لتفويض إشعارات الويب إلى التطبيق وإظهار شارة الأيقونة على أجهزة Android الداعمة.
- ملف التوقيع وكلمة مروره محليان وغير مضافين إلى Git. يجب الاحتفاظ بنسخة آمنة منهما لأن كل تحديث APK لاحق يجب أن يستخدم المفتاح نفسه.
- التحقق كامل الشاشة يعتمد على نشر `/.well-known/assetlinks.json` المطابق لبصمة مفتاح التوقيع.

## البناء

1. شغّل بناء الموقع ومعاينته على المنفذ 4173 لتكون الأيقونات المحلية متاحة.
2. نفّذ `npm exec bubblewrap -- update --manifest=android-twa/twa-manifest.json` عند تغيير إعدادات التطبيق.
3. شغّل `npm run android:build` بعد ضبط متغيري كلمة مرور المفتاح المذكورين في وثائق Bubblewrap.

المخرجات النهائية تكون داخل مجلد `android-twa` ولا تُرفع إلى المستودع تلقائيًا.

## نسخة المالك وفريق العمل — MTA Team

- التطبيق المستقل: `com.multitaskagency.staff`، الإصدار `1.0.0`.
- يبدأ من `/adminmt/login?source=android-staff-app`، والاختصار يفتح بوابة الإدارة أيضًا.
- يستخدم نفس الشعار وتفويض الإشعارات وموارد التطبيق الأصلي، مع اسم مستقل وواجهة دخول الفريق.
- صلاحيات الدخول يحددها حساب المستخدم وخادم الموقع. ملف APK أو رابط دخوله لا يمنحان أي صلاحية.
- إذا كانت جلسة عميل مفتوحة في المتصفح، تعرض البوابة زر تبديل الحساب قبل دخول الفريق. تطبيقات TWA على نفس الموقع قد تشترك في جلسة المتصفح؛ اختلاف اسم الحزمة ليس عزلًا لجلسات الحسابات.

للبناء والتوقيع، من جذر المستودع:

```powershell
npm run android:staff -- -Keystore "PATH/android.keystore" -PasswordFile "PATH/.signing-key-password.txt" -JdkPath "PATH/jdk-17" -SdkPath "PATH/android-sdk"
```

يُقرأ مسارا JDK وAndroid SDK من إعداد Bubblewrap المحلي عند عدم تمريرهما. تستخدم أدوات جافا على Windows مسارًا لاتينيًا؛ لذلك تُنسخ مدخلات البناء فقط إلى مجلد مؤقت مستقل. تُحذف نسخة مفتاح التوقيع المؤقتة بعد التوقيع، ولا تُكتب كلمة المرور في السجل أو المستودع.

الملف النهائي: `android-twa/MTA-Team-1.0.0.apk`. افحص توقيعه واسم الحزمة ورابط التشغيل قبل نسخ الملف المعتمد إلى `public/downloads` وبناء الموقع. يجب نشر سجل التطبيق في `public/.well-known/assetlinks.json` مع صفحة الدخول؛ البصمة المسجلة يجب أن تطابق المفتاح المستخدم. [مرجع ربط عدة تطبيقات بالموقع](https://developer.android.com/training/app-links/configure-assetlinks).

تغيير APK يتطلب زيادة `versionCode` و`versionName` في `staff/build.gradle` واسم المخرج في أداة البناء. تحديث واجهة الموقع لا يتطلب إعادة تثبيت التطبيق.
